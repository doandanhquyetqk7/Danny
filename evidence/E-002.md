## 6. Hàm kiểm tra magic/signature — `0x9141B8`

```asm
00914237  mov  dword ptr [ebp-0x40], 0x120089
0091423e  mov  dword ptr [ebp-0x3c], 0x120116     ; "USB-AT" + "2.6"
00914245  mov  dword ptr [ebp-0x38], 0x1200a0
0091424c  mov  dword ptr [ebp-0x34], 0x1f01ff
00914260  mov  dword ptr [ebp-0x1c], 0x14         ; độ dài 20 byte
...
009141ed  push edi; call 0x418388     ; GENERIC_READ (7)
00914284  call 0x418370              ; đọc 20 byte
00914296  cmp  dword ptr [ebp-0x10], 0
0091429e  je   0x91429e
0091429b  mov  eax, [ebp-0x14]       ; trả về giá trị đọc được
```

Hàm này mở file (access = 7 = `GENERIC_READ`), đọc **20 byte đầu**, so sánh với bảng 4 giá trị
`0x120089 / 0x120116 / 0x1200a0 / 0x1f01ff`. Dùng để xác thực nội dung chỉ dấu **do đúng bộ
công cụ BTL86 sinh ra**, không phải file tự chế đặt tên giống.

> **Điểm yếu (F-04/F-02)**: bảng 4 số nguyên cứng 20 byte — không có kiểm tra chữ ký số
> (RSA/ECDSA). Kẻ tấn công biết 20 byte này có thể tạo `inf.bin` giả. Đây là **nhận diện**, không
> phải xác thực bằng mật mã.

## 11. Ghi log sự kiện (telemetry) — `WritesyslogUSBadd` @ `0x916AC8`

Sinh JSON (đã giải mã string format tại `0x916da4`):

```json
{"disk":"E:","version":"An toan 2.6","serial":"<serial>","diskinfo":"<info>","description":"<desc>"}
```

đóng gói kèm timestamp `yyyy-mm-dd hh:mm:ss` (`0x916d1c`), nhãn
`Plug-In disk: ` (`0x916d50`) + `, disk_info: ` (`0x916d7c`).
`logType` = `Event` (bình thường) hoặc `Alert` (bị chặn).

## 12. Kết luận cơ chế (Confidence: HIGH)

```
Cắm USB
   │
   ├─ MiAV (dịch vụ MiAVWD/MiAVProtect/Defense + MiAV.exe) nhận sự kiện
   │
   ├─ Xác định ổ có phải removable (GetDriveType == DRIVE_REMOVABLE) → nhãn "USB"
   │
   ├─ GetUSBSafeVersion — 3 tầng:
   │   1. isUSBCY    → "CY_*" (USB hãng thứ ba)
   │   2. isUSBATT   → serial "00113335555" → "An toan 3.0"
   │   3. GetTypeUSB → label "USB-AT2.6" (magic 0x120116) + inf.bin + đủ 5 file chỉ dấu
   │                  (esi==7 && ebx==7 | edi==7 && ebx==7) → "An toan <2.6"
   │                  còn lại → "Khong an toan"
   │
   ├─ Đọc C:\Users\Public\Documents\AgentFMC\data\config.ini
   │     [Drive] usb_cy    = block   → USB CY bị khóa
   │     [Drive] usb_at    = block   → USB có an toàn bị khóa
   │     [Drive] usb_no_at = block   → USB không an toàn bị khóa   ← MẶC ĐỊNH
   │
   ├─ Nếu giá trị == "block":
   │     • ghi log "Alert" (0x916AC8)  với JSON disk/version/serial
   │     • Callback Filter khóa I/O toàn bộ <drive>:\* và <drive>:\
   │     • hiện hộp thoại "USB (...) không được phép sử dụng..."
   │
   └─ Nếu khác ("alert"): ghi log "Event" + quét malware trong USB (YARA, remove_malware)
```

**Điểm mấu chốt:** `USB_AnToan_BTL86_Setup(2).exe` (v2.6) tạo ra **volume label `USB-AT2.6`**
+ bộ file `inf.bin`/`Mtext.bin`/... mà MiAV kiểm tra. Vì vậy **USB an toàn phiên bản 2.6 là bắt buộc**
để MiAV không khóa USB — đúng như chính sách quân sự mô tả.
