## 2. Kiến trúc chẩn đoán mạng

Module mới: `NetSecTool/NetDiagnostics.cs` (~700 dòng).

### 2.1. Mô hình dữ liệu

```csharp
internal enum CheckLevel { Ok = 0, Warn = 1, Fail = 2, Info = 3 }

internal sealed class CheckResult
{
    public string Step { get; init; }      // "1. Cong vat ly / Link"
    public CheckLevel Level { get; init; }  // den trang thai
    public string Message { get; init; }   // ket luan 1 dong
    public string Detail { get; init; }    // chi tiet ky thuat
}
```

`CheckLevel` ánh xạ trực tiếp tới màu hiển thị trong GUI:

| Level | Màu | Ý nghĩa |
|---|---|---|
| `Ok` | xanh lá | Bước thành công |
| `Warn` | vàng | Hoạt động nhưng có điểm cần lưu ý |
| `Fail` | đỏ | Lỗi cần can thi |
| `Info` | xanh lá mờ | Thông tin bổ sung |

### 2.2. Quy trình 4 bước

```
Bước 1  Link vật lý     → NetworkInterface.GetAllNetworkInterfaces()
                           OperationalStatus, Speed, MAC, IP unicast
Bước 2  Driver          → WMI Win32_NetworkAdapter
                           ConfigManagerErrorCode, DriverVersion, DHCPEnabled
Bước 3  Gateway/Modem   → FindGateway() + ping.exe
                           đo latency trung bình & packet loss
Bước 3b Modem WAN       → ping 12 địa chỉ đầu trong danh sách 132 đơn vị
Bước 4  Routing/DNS     → tracert.exe tới 86.0.188.1
                           + Dns.GetHostEntry() cho 3 tên miền
```

**Nguyên tắc "best effort":** nếu một bước thất bại (ví dụ không có gateway),
bước sau vẫn chạy và ghi nhận cảnh báo riêng thay vì dừng toàn bộ.

### 2.3. Phát hiện tự động

* **Card mạng:** ưu tiên Ethernet có `OperationalStatus.Up`; nếu không có thì lấy card
  `Up` bất kỳ; cuối cùng mới lấy card đầu tiên.
* **Default Gateway:** đọc từ `IPInterfaceProperties.GatewayAddresses` (IPv4),
  fallback sang WMI `Win32_NetworkAdapterConfiguration.DefaultIPGateway`.
* **IP:** lấy từ `GetIPProperties().UnicastAddresses`, lọc `AddressFamily.InterNetwork`
  và loại loopback.

### 2.4. Parse output

**Ping** — đọc stdout của `ping.exe -n <count> -w <timeout>`, regex `time=([\d<]+)`:

```
  Reply from 171.254.166.209: bytes=32 time=9ms TTL=254
```

Bộ đệm 5 giây cho mỗi lệnh, `Process.Kill()` nếu timeout — bảo đảm phần mềm không treo.

**Tracert** — output thực tế của Windows **đặt IP ở cuối dòng**, không phải đầu:

```
  8   293 ms   293 ms   293 ms  84.116.132.6
```

Vì vậy parser dùng **regex tìm IPv4 ở bất kỳ vị trí nào** trong dòng, kèm regex
`(\d+)\s*ms` cho RTT. Các hop không phản hồi (`*`) bị bỏ qua.

> **Bẫy đã gặp:** bản đầu tiên dùng `rest.Split(' ')[0]` để lấy IP → lấy nhầm số
> "293" làm IP, hiển thị "Hop cuoi: 301". Đã sửa bằng regex.

`lastHop` lấy là `trace.Hops.Keys.Max()` (hop cao nhất thực sự phản hồi), **không phải**
`trace.Hops.Count` — vì các hop timeout làm count nhỏ hơn số hop thật.

### 2.5. Báo cáo

`BuildReport()` sinh văn bản có đầy đủ: thời gian, tên máy, người dùng, OS, card mạng,
IP, gateway, kết quả từng bước, thống kê OK/Warn/Fail và kết luận tổng.
Ghi file UTF-8 **có BOM** để Notepad trên Windows hiển thị đúng tiếng Việt.

## 4. Đóng gói phần phối "Danny"

### 4.1. Đổi tên assembly

```xml
<AssemblyName>Danny</AssemblyName>
<Product>Danny ver1.0 - Trợ lý Công nghệ Thông tin</Product>
<AssemblyTitle>Danny ver1.0 - Trợ lý Công nghệ Thông tin</AssemblyTitle>
<Company>Bộ Chỉ huy Quân sự tỉnh Lâm Đồng</Company>
<Version>1.0.0</Version>
```

### 4.2. Hai bản phân phối

| Bản | Lệnh publish | Kích thước |
|---|---|---|
| **Self-contained** (khuyến nghị) | `-r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true` | 69 MB |
| **Framework-dependent** | `-p:PublishSingleFile=true -p:SelfContained=false` | 1.25 MB |

Bản self-contained nhúng sẵn .NET 8 runtime → chạy được trên máy quân sự không
cài .NET. Bản framework-dependent nhẹ hơn 55 lần, dành cho máy đã có runtime.

### 4.3. Tách KVRT.exe ra khỏi bundle

`KVRT.exe` (Kaspersky offline) nặng **114 MB**. Nhúng vào exe làm file phân phối
phình to 184 MB (self-contained) — không thực tế để đưa cho người dùng.

Giải pháp: copy sang thư mục `tools/` kèm theo, kèm
`<ExcludeFromSingleFile>true</ExcludeFromSingleFile>` để .NET **không** nhúng lại
vào bundle:

```xml
<None Include="Resources\KVRT.exe" Link="tools\KVRT.exe">
  <CopyToPublishDirectory>PreserveNewest</CopyToPublishDirectory>
  <ExcludeFromSingleFile>true</ExcludeFromSingleFile>
</None>
```

Kết quả: exe 184 MB → **69 MB**. Nếu thiếu file, nút "Chạy Kaspersky" hiện thông báo
rõ ràng thay vì làm app chậm.

### 4.4. Cấu trúc thư mục phân phối

```
Danny-ver1.0\
├── Danny-ver1.0.exe            69.1 MB   ← bản khuyến nghị
├── Danny-ver1.0-nethost.exe     1.25 MB  ← bản nhẹ
├── tools\KVRT.exe             114.5 MB   ← Kaspersky offline
└── HUONG-DAN-SU-DUNG.md
```

Đóng gói thành `Danny-ver1.0.zip` (177.53 MB).

> Tên file **không dùng khoảng trắng** (`Danny-ver1.0.exe` thay vì `Danny ver1.0.exe`)
> để không rắc rối khi gọi từ CMD/PowerShell và tránh nhầm với bản cũ.

### 4.5. Chế độ CLI

`Program.cs` hỗ trợ chạy headless (không MessageBox) cho tự động hoá:


## 6. Guard mới: ổ đĩa không tồn tại

Phát hiện trong lúc kiểm thử: `--check "J:\"` trên ổ không cắm vẫn in ra kết quả
như thể ổ tồn tại ("Quyen ghi thu muc goc: da chan → MiAV se cong nhan o la an toan") —
**kết luận sai**, có thể khiến người dùng tin nhầm USB đã an toàn.

Đã thêm guard ở đầu cả `MakeSafeUsb()` và `InspectUsbSafe()`:

```csharp
if (!Directory.Exists(root))
{
    sb.AppendLine("O dia " + root + " KHONG TON TAI hoac khong san sang.");
    sb.AppendLine("Hay cam lai USB roi thu.");
    return sb.ToString();
}
```

Kèm `GetFileSystem()` cũng trả về `""` nếu ổ không tồn tại, để không hiển thị
"Định dạng: (không hỗ trợ DACL)" gây hiểu nhầm.

## 7. Ghi chú kỹ thuật

### 7.1. `System.Management` (WMI)

Bổ sung PackageReference `System.Management 8.0.0` để đọc
`Win32_NetworkAdapter.ConfigManagerErrorCode` — mã lỗi Device Manager.
Không dùng được `Get-NetAdapter` (PowerShell) vì chậm và phụ thuộc module.

Mọi truy vấn WMI đều bọc `try/catch` → nếu WMI bị chặn bởi policy, bước 2 trả về
cảnh báo "Khong doc duoc thong tin driver qua WMI" nhưng vẫn tiếp tục các bước sau.

### 7.2. UTF-8 BOM bắt buộc

Tất cả file `.cs` giữ **UTF-8 BOM**. Không có BOM, Roslyn đọc file bằng encoding
mặc định của hệ thống → chuỗi tiếng Việt trong source bị hỏng (`C? H? TR?`).

### 7.3. `ExcludeFromSingleFile`

Không có property này, `tools\KVRT.exe` vẫn bị .NET nhúng vào bundle single-file
dù đã đặt `CopyToPublishDirectory`. Chỉ có `ExcludeFromSingleFile=true` mới
thực sự tách file ra khỏi bundle.
