# E-007 — Bố cục ACL "DATA" cho USB An Toàn 2.6 (thay đổi lớn)

**Ngày:** 2026-10-30
**Phạm vi:** `NetSecTool/UsbSafeMaker.cs`, `NetSecTool/UsbSafeService.cs`, `NetSecTool/Form1.cs`
**Ổ thật kiểm thử:** `J:` (USB "911-DANNY", 7.81 GB, NTFS)

---

## 1. Vấn đề

Lần tạo USB An Toàn đầu tiên **đã pass end-to-end trên máy quân sự có MiAV**
(kernel minifilter `cbfilter20.sys` không chặn ổ), nhưng người dùng **không ghi được
bất kỳ file nào** — kể cả tạo thư mục con:

```
Destination Folder Access Denied
```

### Nguyên nhân gốc

Bản đầu áp `Deny Write` cho **toàn bộ cây thư mục gốc** kèm kế thừa `(OI)(CI)`:

```
J:\ Everyone:(OI)(CI)(DENY)(DE,WD,AD,WEA,DC,WA)
    Everyone:(OI)(CI)(F)
```

ACE `Deny` kế thừa xuống mọi thư mục/file con ⇒ **không nơi nào ghi được**.

### Xác nhận cơ chế MiAV

Đã xác minh lại bằng disassembly (`work/verify_accesscheck.py`):

- Chuỗi tại `MiAV.exe 0x915320` = `":\\"` ⇒ đường dẫn dùng cho `AccessCheck`
  là **chính thư mục gốc** `<drive>:\`, **không** quét đệ quy.
- `AccessCheck` với `FILE_GENERIC_WRITE` (`0x120116`):
  - User **có** quyền ghi ở root ⇒ `MiAV` gán `"Khong an toan"` (`0x91537C`) ⇒ khoá ổ ở kernel.
  - User **không** quyền ghi ở root ⇒ đủ 5 file chỉ dấu ⇒ `"An toan 2.6"`.

> **Kết luận then chốt:** chỉ cần chặn ghi ở **thư mục gốc**. Thư mục con có
> DACL riêng không ảnh hưởng tới việc MiAV phân loại ổ.

## 2. Bố cục mới

```
J:\  ── DACL: Deny Write/Delete (Everyone)  ← điều kiện MiAV
│
├── DATA\  ── DACL: Allow Read/Write/Delete, Deny ExecuteFile (Everyone)
│              ├── tài liệu.txt      → ghi/đọc/xoá ĐƯỢC, chạy KHÔNG
│              └── virus.exe         → copy ĐƯỢC, chạy KHÔNG ĐƯỢC
│
├── RECYCLER\
├── inf.bin, mtext.bin, autorun.inf, attt.ico   (Hidden + System, chỉ đọc)
└── System Volume Information\
```

### ACL chi tiết (đọc từ `icacls` sau khi tạo)

```
J:\          Everyone:(OI)(CI)(DENY)(DE,WD,AD,WEA,DC,WA)
             Everyone:(OI)(CI)(F)

J:\DATA      Everyone:(OI)(CI)(DENY)(X)
             Everyone:(OI)(CI)(R,W,D)

J:\DATA\cmd.exe   Everyone:(I)(DENY)(X)
                  Everyone:(I)(R,W,D)
```

`X` = `ExecuteFile` (0x1) — quyền chạy file thực thi.

## 3. Ba lỗi ACL đã phát hiện và sửa

### Lỗi 1 — Thứ tự áp DACL

`ApplySafeLayout` ban đầu gán ACL cho `DATA` **trước**, khoá gốc **sau**.
Khi `ApplyDenyWriteToDirectory` thêm ACE `Deny` có kế thừa `(OI)(CI)` lên thư mục gốc,
Windows **tự động đẩy ACE Deny đó xuống mọi thư mục con đã tồn tại** — kể cả `DATA`.
`Deny` thắng `Allow` ⇒ `DATA` bị chặn ghi.

**Sửa:** đảo thứ tự — tạo `DATA` → khoá gốc (bỏ qua cây `DATA`) → gán DACL riêng cho
`DATA` với `SetAccessRuleProtection(true, false)` để **cắt kế thừa**.

```csharp
public static void ApplySafeLayout(string root)
{
    string dataPath = Path.Combine(root, DirData);
    Directory.CreateDirectory(dataPath);      // 1. tạo DATA trước

    ApplyDenyWriteRecursive(root);           // 2. khoá gốc (skip DATA)

    ApplyDataFolderAcl(dataPath);             // 3. DACL riêng cho DATA
}
```

### Lỗi 2 — `RestoreWriteAccess` xoá sạch DACL gốc

Code cũ dùng `GetAccessControl(AccessControlSections.None)` rồi `SetAccessControl()`.
Với `Sections.None`, .NET ghi **một security descriptor rỗng** — làm mất toàn bộ ACE
(bao gồm ACE `Deny` mà MiAV cần). Hệ quả: sau khi bấm "Mở khóa", ổ **mất trạng thái
an toàn vĩnh viễn** cho tới lần tạo lại.

**Sửa:** dùng `AccessControlSections.Access` + `SetAccessRuleProtection(true, false)`
để cắt kế thừa mà **giữ** các ACE Allow hợp lệ.

### Lỗi 3 — DACL "corrupt" trên file chỉ dấu từ lần tạo trước

`J:\mtext.bin` còn sót DACL hỏng (explicit `Everyone:(R)` + inherited `Allow`).
`SetAccessControl` bị `UnauthorizedAccessException`, kể cả khi root đã ghi được.

**Sửa:** thêm `ForceResetFileAcl()` — dùng quyền `WRITE_DAC` implicit của owner để
ghi đè DACL, và xoá file chỉ dấu cũ trước khi ghi lại.

```csharp
public static bool ForceResetFileAcl(string filePath) { ... }
```

## 4. Kết quả kiểm thử trên ổ thật `J:`

### 4.1. Bộ test tự động (`work/dataacltest/`)

Dùng PE thật (`C:\Windows\System32\cmd.exe`) làm file thử:

| # | Hành vi kiểm tra | Kết quả |
|---|---|---|
| 1 | Ghi ở thư mục gốc | ✅ bị chặn (điều kiện MiAV) |
| 2 | Ghi trong `DATA/` | ✅ ghi được |
| 3 | Đọc trong `DATA/` | ✅ đọc được |
| 4 | Chạy PE thật trong `DATA/` | ✅ bị chặn |
| 5 | Xoá file trong `DATA/` | ✅ xoá được |
| 6 | Tạo file mới trong `DATA/` | ✅ tạo được |
| 7 | Copy PE thật vào `DATA/` | ✅ copy được |
| 8 | DACL có `Deny ExecuteFile` | ✅ có |
| 9 | Chạy PE sau khi mở khoá | ✅ chạy được (đúng thiết kế) |

**→ PASS 9/9**

### 4.2. Kiểm chứng trực tiếp trên `J:` (PowerShell)

```

=== B. DATA ghi duoc ===                  DUNG
=== C. DATA doc duoc ===                  DUNG
=== D. Copy .exe vao DATA ===             DUNG - copy duoc
=== E. Chay .exe trong DATA ===           DUNG - bi chan

Lỗi cụ thể khi cố chạy file thực thi trong `DATA/`:

```

### 4.4. Idempotency

Chạy `--make-safe "J:\"` lần thứ hai trên ổ đã khoá: tự động mở khoá tạm,
ghi lại bộ chỉ dấu, khoá lại — kết quả giữ nguyên trạng thái đúng.

## 5. Giao diện

Redesign phong cách quân đội (`NetSecTool/Form1.cs`):

- Tông chủ đạo: **xanh lá cây đậm** `#174A2C` / `#22683E`, **đỏ** `#9E1616` / `#C42A2A`,
  **vàng** `#D6B03A` / `#A07E1A`.
- Header xanh lá đậm + sọc đỏ/vàng, phân mục có đường kẻ ngang.
- **Log panel nền terminal** (`#0E1E14`, chữ xanh `#8EE896`) thay cho MessageBox.

### Bỏ các hộp thoại gây rối

| Trước | Sau |
|---|---|
| MessageBox xác nhận tạo USB (dài, nhiều dấu `•`) | **Đã bỏ** — ghi thẳng vào log panel |
| MessageBox kết quả tạo USB | **Đã bỏ** — log panel |
| MessageBox kết quả kiểm tra | **Đã bỏ** — log panel |
| MessageBox kết quả mở khoá | **Đã bỏ** — log panel |
| MessageBox xác nhận xoá Event Viewer | **Giữ** (không liên quan tới tạo USB) |
| MessageBox xác nhận format NTFS (mất dữ liệu) | **Giữ** — bắt buộc, chỉ hiện khi thật sự cần format |

### Lỗi encoding UTF-8

Các file `.cs` thiếu BOM ⇒ Roslyn đọc theo ANSI codepage ⇒ tiêu đề hiển thị
`C? H? TR?`. Đã thêm BOM UTF-8 cho toàn bộ source và khôi phục dấu tiếng Việt.

## 7. Lưu ý bảo mật

Bộ kiểm tra của MiAV là **tự tham chiếu**: seed `K` lấy từ chính file đang kiểm tra,
không có khoá công khai, không có chữ ký số. Vì vậy:

> "USB An Toàn 2.6" **không phải** cơ chế xác thực — đó là *marker* do người dùng
> tự khai. Ràng buộc thật sự duy nhất là **DACL**.

Xem `report/report.md` mục 4bis để biết chi tiết cơ chế và các hạn chế đã nêu.
