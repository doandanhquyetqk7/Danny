## 3. File mới: `NetSecTool/UsbSafeMaker.cs`

Module logic thuần, không phụ thuộc UI — có thể dùng lại như thư viện.

### 3.1 Công thức `inf.bin` (chuyển từ `work/make_infbin.py` sang C#)

```
K    = Lines[2]                      (seed, lấy từ chính file đang kiểm tra)
k1   = Lower(MD5(K))
k2   = Lower(MD5(k1))
E(X) = X XOR k2 XOR k1 XOR K        (kéo dài, khóa lặp theo CHỈ SỐ KÝ TỰ)

V0   = E(Base64Decode(Lines[0]))    → "2.6"   (phiên bản)
V1   = E(Base64Decode(Lines[1]))    → "BTL86" (hãng SX)
L3   = Lower(MD5(V0 + V1 + K))       ← tính trên PLAINTEXT
```

> **Lưu ý triển khai (sửa được 1 lỗi khi chuyển đổi):** `L3` là MD5 của **plaintext**
> (`"2.6" + "BTL86" + K`), **không** phải của ciphertext. Vì XOR là phép tự nghịch đảo
> (`E(E(x)) = x`), nên `E(ciphertext)` cho lại plaintext. Bản C# ban đầu mắc lỗi này và
> cho ra `f41ed76b…` thay vì `54c7bca3…`; đã sửa và kiểm chứng lại.

### 3.2 Bộ 5 file chỉ dấu (đếm đúng theo `GetTypeUSB`)

`GetTypeUSB` (`0x914f28`) quét thư mục gốc, đếm biến `[ebp-0x280]`, và so sánh `== 5`
tại `0x915092`. Tên file nó đếm:

| Tên | Địa chỉ chuỗi |
|---|---|
| `recycler` | `0x9151bc` |
| `autorun.inf` | `0x9151dc` |
| `inf.bin` | `0x9152e4` |
| `mtext.bin` | `0x915238` |
| `attt.ico` | `0x915300` |

Ngoài ra `GetTypeUSB` còn dùng `esi`/`edi` để đếm các file *không* thuộc bộ an toàn
(`data`, `recycler`, `autorun.inf`, `hdsd usb an toan.chm`, `mtext.bin`, `vkt.ico`,
`reformat usb.exe`, `system volume information`) và yêu cầu `esi == 7` / `edi == 7`
để xếp loại **"An toan <2.6"**. Ổ tạo mới chỉ có 5 file → không đạt "An toan <2.6",
mà rơi đúng vào nhánh **"An toan 2.6"** (`0x91509b`).

### 3.3 DACL — điều kiện bắt buộc để MiAV không khóa ổ

`0x915048` gọi `MapGenericMask` với `0x120116` (= `FILE_GENERIC_WRITE`) rồi `AccessCheck`
trên `<drive>:\`. Kết quả:

- **User CÓ quyền ghi** → phân loại **"Khong an toan"** → MiAV gọi `set policy usb_no_at = block`
  → minifilter `cbfilter20.sys` chặn ở tầng kernel.
- **User KHÔNG có quyền ghi** → nếu đủ 5 file chỉ dấu → **"An toan 2.6"** → không khóa.

Do đó `MakeUsbSafe` áp **DACL Deny** cho `Everyone` trên thư mục gốc + toàn bộ cây con:

```
Deny  : Everyone → Write | Delete | DeleteSubdirectoriesAndFiles
Allow : Everyone → ReadAndExecute | Synchronize
```

Áp dụng theo thứ tự **con trước, gốc sau** (vì sau khi khóa gốc sẽ không tạo được file mới).

### 3.4 `attt.ico`

Sinh icon 16×16 32bpp hợp lệ tại runtime (1150 byte, `ICONDIR` + `BITMAPINFOHEADER` +
XOR bitmap + AND mask). Không nhúng resource tĩnh để tránh phụ thuộc file nhị phân ngoài.

### 3.5 Bước format NTFS (`NetSecTool/UsbFormatter.cs`)

DACL chỉ tồn tại trên NTFS. FAT32/exFAT không có khả năng đó → `SetAccessControl` thất bại →
user vẫn ghi được → MiAV phân loại "Khong an toan" → khoá ổ ở kernel. Vì vậy phải format
NTFS **trước** khi gắn DACL.

#### 3.5.1 Phát hiện lỗi thật: `format.com` **thất bại** trên USB 7.8 GB

Lệnh chuẩn của sản phẩm BTL86:

```
C:\Windows\System32\format.com J: /FS:NTFS /V:USB-AT2.6 /Y /Q
```

Trên USB "911-DANNY" (USB2.0 Flash Disk 7.81 GB) lệnh này cho:

```
The type of the file system is FAT32.
The new file system is NTFS.
QuickFormatting 7,8 GB
Creating file system structures.
Format complete.
       7,8 GB total disk space.
       7,8 GB are available.
Format failed.            ← exit code 4
```

Event Log (`Ntfs`, Id 55): *"The Master File Table (MFT) contains a corrupted file record."*

**Nguyên nhân**: NTFS cấp phát **MFT zone** (vùng liên tục lớn ở đầu đĩa). Trên ổ 7.8 GB
cấu trúc MFT không thoả điều kiện → format fail. **Thử nghiệm chứng minh**: trên *cùng
USB đó*, tạo partition 2 GB → format NTFS **thành công** → `extend` partition lên toàn bộ
7.81 GB → NTFS vẫn bình thường, ghi/đọc/DACL đều ổn.

#### 3.5.2 Chiến lược 2 giai đoạn (đã hiện thực)

| Giai đoạn | Lệnh | Mục đích |
|---|---|---|
| 1 | `diskpart`: `select disk N` → `clean` → `create partition primary size=2000` | Tạo partition **trống** kích thước nhỏ |
| 2 | `diskpart`: `select partition 1` → `format fs=ntfs label=<nhãn> quick` | Format NTFS trên partition nhỏ → **thành công** |
| 3 | `diskpart`: `select partition 1` → `extend` | Mở rộng partition chiếm hết đĩa |
| 4 | `diskpart`: `assign letter=<X>` | Gán lại ký tự ổ đĩa |

Luồng thực thi trong `UsbFormatter.EnsureNtfs`:

1. Nếu đã là NTFS → bỏ qua (`Skipped = true`).
2. **Chiến lược 1**: thử `format.com` thuần (nhanh, giữ nguyên partition).
3. Nếu thất bại → **chiến lược 2**: 4 giai đoạn diskpart ở trên.
4. Xác minh lại bằng `DriveInfo.DriveFormat` phải trả về `"NTFS"`.

Số thứ tự disk được lấy bằng `diskpart /s` với `select volume X:` + `detail volume`,
parse dòng `* Disk N` — không phụ thuộc WMI/`System.Management`.

#### 3.5.3 Xác nhận xoá dữ liệu

Hộp thoại xác nhận (UI) hiển thị trước khi format:

- Ổ đích, nhãn cũ, định dạng cũ → mới
- Giải thích **lý do** kỹ thuật (DACL → `AccessCheck` → MiAV khoá ổ)
- Cảnh báo in đậm: *"TOÀN BỘ DỮ LIỆU TRÊN Ổ SẼ BỊ XOÁ VÀ KHÔNG KHÔI PHỤC ĐƯỢC"*
- Số mục + dung lượng hiện có ở thư mục gốc
- Nút mặc định là **Button2** (mặc định = No) để tránh bấm nhầm

#### 4.5.2 Sự cố & cách khắc phục

Lần chạy đầu tiên dùng `format.com` thuần → **thất bại** ("Format failed", exit 4),
USB rơi vào trạng thái `RAW` (volume 0 byte, không mount được).

Khắc phục bằng chiến lược 2 giai đoạn:

```
clean → create partition primary size=2000 → format fs=ntfs → extend
→ J: NTFS 7.81 GB, nhãn USB-AT2.6, ACL Everyone:(F), ghi được
```

> **Phát hiện thêm**: sau khi gắn Deny `Everyone`, **cả admin cũng không gỡ được ACL**
> (`icacls /reset` → "Access is denied") vì Deny thắng Allow. Cách gỡ đúng là
> `SetOwner` + `SetAccessRule` (đã hiện thực trong `UsbSafeMaker.RestoreWriteAccess`),
> hoặc reset lại partition.

## 5. Lưu ý bảo mật & vận hành

1. **Cơ chế "USB an toàn 2.6" của BTL86 không phải là xác thực.** Seed lấy từ chính file
   đang kiểm tra, không có khóa công khai, không có chữ ký số, không ràng buộc serial/UUID
   ổ USB. Ai cũng có thể tạo ra một `inf.bin` "hợp lệ". Bản đóng gói `USB_ATTT.exe` có
   thêm bước DACL (khóa quyền ghi) — **đây mới là ràng buộc thật**, và MiAV kiểm tra nó
   bằng `AccessCheck`. Do vậy "tạo USB an toàn" thực chất là *"đặt đúng 5 file chỉ dấu +
   khóa quyền ghi"*, không phải *"chứng minh USB là an toàn"*.
2. **Khóa quyền ghi là chặn hai chiều.** Sau khi khóa, MiAV sẽ không khóa ổ, nhưng
   người dùng cũng không sao chép dữ liệu ra. Nút "Mở khóa quyền ghi" dùng để gỡ lại —
   nhưng khi đó MiAV sẽ coi ổ là "Khong an toan" và khóa ổ.
3. **DACL Deny cộng dồn — kể cả admin.** Deny ở thư mục gốc với `ContainerInherit` kế thừa xuống toàn bộ
   cây; các file con có Deny riêng nên gỡ khóa phải duyệt cây (đã hiện thực trong
   `RestoreWriteAccess`). Lưu ý: **Deny thắng Allow** nên sau khi gắn, `icacls /reset` /
   `takeown` sẽ báo "Access is denied" — phải dùng `SetOwner` + `SetAccessRule` để gỡ.
4. **`format.com` FAT32→NTFS thất bại trên USB lớn.** Xem §3.5.1: lệnh in "Format complete"
   rồi "Format failed" (exit 4), MFT record hỏng. Đã xử lý bằng chiến lược
   *tạo partition 2 GB → format NTFS → extend* (§3.5.2).
5. **Đã kiểm thử thực địa trên USB vật lý "911-DANNY"** (§4.5) — đạt đủ 3 điều kiện của
   `GetTypeUSB`. Chưa kiểm thử trên máy có cài MiAV (máy này không có `cbfilter20.sys`).
6. **Sao lưu dữ liệu trước khi format** là bắt buộc — thao tác này xoá toàn bộ ổ.
